4How it works

The game, start to finish

Pick group→Brief→Round 1 (max 50 of 100 coins)→Submit — row saved→Reveal code→3 setbacks revealed→Round 2 (coins left)→Submit — score saved→Year in review

Round 1 picks decide three setbacks. Leak: no Guardrails costs 20 points. Board: no Pilot halves the coins left for round 2. Adoption: neither Training nor the Managers workshop costs 20 points. Round 2 offers recovery options only for setbacks that hit, plus two growth options; Take It Company-Wide pays full points only if the group had both a pilot and a people option. Final score = points from picks − penalties, kept between 0 and 100. The best possible game scores 90.

Each device remembers its game in the browser, so a refresh doesn't lose progress. Reset (tap twice) clears it for the next group.

Pages call the server with google.script.run, so a group always knows whether a send worked. On failure they see “Couldn't send… tap again” and keep their answers. The scoreboard ranks each group by its latest round 2 row; a group with only a round 1 row shows “Playing…”.

Security is deliberately light: anyone with the game link can submit, and scores are calculated on the phone. Fine for a room of guests. The reveal code is checked on the server and never sent to phones.

5Rebuild it from scratch (about 10 minutes)

  1. Create a blank Google Sheet, then open Extensions → Apps Script.
  2. Replace Code.gs with the repo's apps-script/Code.gs. Add three HTML files named exactly index, dashboard and feedback, and paste in the matching files. Save.
  3. Pick setup in the function dropdown and click Run. Approve the permission prompt (Advanced → Go to project → Allow). The five tabs appear with the original game's content.
  4. Deploy → New deployment → gear → Web app. Execute as Me, access Anyone. Copy the URL ending in /exec.
  5. Paste that URL into WEB_APP_URL in the Config tab. Reload the sheet, then Task Force → Show page links.
  6. Play one full test game on a phone, then tap Start a new event on the scoreboard to clear it.

Quickest alternative: File → Make a copy of the live sheet. The script is copied with it; just deploy the copy (step 4) and set its WEB_APP_URL. A script made at script.google.com instead of from the sheet also works: put the sheet's ID in SHEET_ID at the top of Code.gs. It won't have the sheet menu.

6On the day

  1. Before guests arrive: scoreboard on the room screen, tap Start a new event twice. All groups read “Not started”.
  2. Groups scan the game QR, tap their table number and play round 1.
  3. When every group shows “Playing…”, read out the reveal code.
  4. Groups play round 2. Scores appear within 15 seconds; click a row to show that group's moves.
  5. Closing slide: feedback QR. Responses land in the Feedback tab.

For a different activity altogether (a quiz, a poll, a sign-up), keep the skeleton: doGet routing, a page that calls google.script.run, an append_ call that writes one row, and a read function for a live board. Try changes on a copy of the sheet first (File → Make a copy brings the script along) with its own deployment, so the live links stay untouched.

SymptomFix

Guests are asked to sign in to GoogleDeployment access must be Anyone. If your Google Workspace admin doesn't allow that, deploy from an account that does.

Scoreboard says “Connection error”It retries on every refresh. If it persists, open the web app URL directly to check the deployment.
